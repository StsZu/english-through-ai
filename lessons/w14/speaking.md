# Speaking — w14: Additional Activities & Lifelong Fluency

Model answers for reading and review. Personal stories and examples are illustrative, not real events.

## 1. Which post-course activities resonate most with your daily engineering work? How do you assess your current 4D proficiency?

**Answer:**  
The activity that resonates most with my work is building a personal prompt and pattern library, because I repeat many similar tasks in the terminal and on the router. The personal AI fluency plan is also useful for me. To assess my proficiency, I rate each of the four Ds as novice, developing or confident, and I write down my strengths and weak points. For example, I feel confident with delegation, but my discernment with complex code is still developing.

## 2. How do you organize reusable prompt templates with placeholders to streamline recurring infrastructure and coding tasks?

**Answer:**  
I keep my templates in one folder as text files, grouped by topic: network, git, Python and English. Each template has placeholders for the parts that change, like [DEVICE], [GOAL] or [ERROR MESSAGE]. I also save an example of a good result next to each template. When I find a better version, I update the template, so the library grows with my experience.

**Example:**  
"On a MikroTik [MODEL] with RouterOS [VERSION], I need to [GOAL]. Explain each command before I run it, and do not change the firewall." I only fill in the brackets.

## 3. Why are playful exercises and tricky riddles effective for training conversational steering and chain-of-thought nudging?

**Answer:**  
Puzzles and riddles have clear rules and one correct answer, so they are good practice for precise description. They are also tricky on purpose, so the AI often makes mistakes, which gives me a lot of discernment practice. Instead of telling the AI the answer, I gently nudge its chain of thought with small hints. These steering skills are useful later in real projects, when an AI goes in the wrong direction.

**Example:**  
In a crossword, I can say: "Remember, it has only five letters" or "Maybe 'swallow' means the bird, not drinking." These are the same kinds of nudges I use when an agent misunderstands a task.

## 4. How do you ensure logical coherence and a cohesive theme when collaborating with AI on complex multi-step refactors?

**Answer:**  
First, I describe the goal of the whole refactor, so every step follows the same idea. Then I split the work into small steps and review each one before the next one starts. After each step, I check that the code is still consistent: the same naming, the same style and no broken connections between files. If the AI starts to drift away from the plan, I stop it and remind it of the original goal.

**Example:**  
Before a refactor, I ask the AI to write a short plan into a file. Every new step starts with "Follow the plan in this file", so the work stays connected.

## 5. Describe how you would tackle a thorny algorithmic challenge using self-directed human-AI pair programming.

**Answer:**  
First, I try to understand the problem myself and write down a simple, slow solution. Then I use the AI as a pair programmer: I explain my idea and ask it to find weak points, not to write the full solution. We discuss different approaches, and I write the main code myself while the AI helps with tests and small bugs. At each step, I check its reasoning, because my goal is to learn, not just to get an answer.

**Example:**  
For a Project Euler problem, I can write a brute-force version first. Then the AI and I look for a faster method, and I compare the results of both versions to check that the new one is correct.
