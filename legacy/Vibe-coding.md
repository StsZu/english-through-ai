What problems do we have with vibe coding? When we formulate a task, we leave a lot of things unsaid because it seems obvious to us, or we simply forget to mention something. There’s even a cognitive bias called the curse of knowledge: if you know something, it seems like everyone else already knows it too, so we usually just don’t say it. And in principle this is one of the problems of vibe coding — that when we set a task, we periodically forget something.

With vibe coding we skip a very important part of building a product, which I would call thinking through or this process of deliberating how we’re going to build this project. When we write a requirement to the artificial intelligence and something is missing, it usually fills in what wasn’t there and can do something extra. And in principle we can somehow miss that, which also isn’t very cool, because an agent or artificial intelligence doesn’t have a criterion like “done”. Ideally there should be a formally written technical specification with what we consider the task finished. There should be fairly serious requirements for this process, and in vibe coding there simply isn’t any of that.

And the last problem I want to mention is that when we vibe-code something, we later can’t remember why exactly it was done that way. Because the entire context stays in our chat, in the dialogue with the artificial intelligence. And later, after some time, it’s very hard for us to recall why exactly we did it this way and not another way. If you’ve ever vibe-coded some large projects — not just some small little project of a couple of pages, but something fairly big — then later problems start appearing like a lot of interconnected modules or features, and this whole system starts falling apart, and you simply don’t understand why it’s falling apart, what to do with it, how to put it back together. And then you can’t understand why it was done exactly that way. Because at some point it was vibe-coded, the artificial intelligence asked some questions, you gave it some answers to those questions, it drew its own conclusions based on your incomplete or partially complete answers.
